# Real-data evaluation

The partition example is separate from the historical measurement totals below. `test/fixtures/partition-tracker.json` was acquired from the public `unbraind/pm-unit` tracker at commit `0578835e5d5b46aac334bb8368905deb04530b61`. Acquisition archived only that revision's `.agents/pm` tree to a disposable no-git directory, used the pinned SDK's `listAllComplete` and full `get` reads there, and retained eight `(id, type, item_hash)` rows. The original checkout was read-only. The fixture's SHA-256 covers compact JSON of its repository, revision, URL and ordered rows (excluding the checksum itself): `e1ae4828d9d104ffbdb2862f0c00b4c1794be1cd18ef09c509c8ae3fa861464f`.

Seven rows are Features and one is an Epic. `test/partition-public.test.ts` checks unique IDs, disjoint type membership and an exhaustive union before recording the copied evidence in a new SDK tracker. Both quantities share the pinned revision as their window and use different membership digests. Without a declaration the sum refuses. An explicit reviewed declaration pins those operands and the union membership, and the result is exactly eight items with the review evidence retained. Native hashes identify the copied source revisions; they do not assert a current coherent snapshot, completion, reviewer authentication or source truth. No live source or private repository is accessed by this test.

The separate day-over-day corpus in `test/fixtures/daily-pageviews.json` pins the full response bytes from the public [Wikimedia pageviews API](https://wikimedia.org/api/rest_v1/metrics/pageviews/per-article/en.wikipedia/all-access/user/TypeScript/daily/20240101/20240102), retrieved on November 6, 2026. Its SHA-256 is `0a374cd5be65b68b482c79f6d9890660865e765a58ff41aa487bbef94226b242`. It reports 722 views on January 1, 2024 and 965 on January 2 for English Wikipedia's TypeScript article, `all-access`, `user`, `daily`. These are views classified as user traffic, not unique people. Daily boundaries follow UTC, as used in the [official Wikimedia comparison tutorial](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/tutorials/compare-page-metrics.html). The shared population digest pins the same filter definition, not identical visitor identities. `test/cross-window.test.ts` creates a real non-Git SDK tracker, anchors that external response in a native source item, records both observations with the native revision and source pointer, and verifies default `window_mismatch`, explicit ordering `-1`, both windows and the held constants. Comparisons leave native history unchanged. This is numerical ordering of reported values; historical API corrections, source truth and causal interpretations remain unknown. The pair is separate from the fleet receipt totals below; no fleet receipt's unknown measurement window is fabricated.

The evaluator copies the Git-tracked `.agents/pm` trees from pinned public revisions into fresh non-Git directories, certifies complete SDK reads, and extracts reported numeric claims from native measurement comments. It never modifies either source tracker. Receipt timestamps are retained as reported acquisition times; actual measurement windows explicitly remain unknown. Native item hashes, source-fragment SHA-256 digests, field pointers and public commit URLs are retained in `test/fixtures/measurements.json`; source bodies are not copied into the quantity ledger.

Run `npm ci`, `npm run build`, then `npm run test:real-data` from the repository root. This uses the pinned, sanitized public fixture and writes the ignored `real-data.local.json` report. From that root, `node test/real-data.acceptance.ts --refresh --write-receipt` explicitly regenerates the fixture and committed receipt from sibling public fleet checkouts, the NASA public fact sheet and this repository's [policy examples](policy-examples.md). It requires only the public `pm-vcs` and `pm-rl` checkouts with the pinned commits available locally, plus network access to NASA. Alternatively, invoke the script by its path from any directory: inputs, outputs and sibling checkouts resolve from the script's repository, not the caller's working directory. Acquisition verifies the pinned physical-source digest and preserves the original acquisition timestamp; changed source content requires review. Each selected claim is logged as JSON with its source pointer, match offset and bounded text excerpt for maintainer review. Explicit `pair_of` and `pair_role` fields link reported fractions independently of fixture ordering. The shipped runtime performs no source scanning or network access.

The receipt, its `implementation_digest` and the timing above cover only the runtime named in `measured_runtime`; they are not cross-version results. Packed acceptance separately exercises Node 22.19.0, Node 26.13.0 and native Bun, without extending that single-runtime receipt to the other runtimes.

The corpus contains 24 count observations, six MiB sizes, four durations in seconds, four percentages and six token counts from 17 native source items, plus three physical measurements from the [NASA Earth Fact Sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/earthfact.html). Their declared exact decimals are converted through an independent BigInt integer oracle, using factors and decimal denominators calculated outside the package kernel. Each expected and actual rational is present in the local report. The physical source is pinned by its fetched SHA-256; these are reported physical measurements, not assertions of exact real-world truth.

The ten-second elapsed versus twenty-second summed-duration controls are explicitly illustrative; they do not increase the 47 measured-claim denominator.

Predeclared controls refuse a test-count versus MiB comparison, count versus tokens, distinct test-run populations, Earth equatorial versus polar radius, elapsed versus summed duration, and total versus cached token semantics. The two unsafe additions refuse an unwitnessed count partition and a total-plus-subset sum. The cached-subset value is unknown because the selected policy source publishes no count; the derived ratio stays null and names `tokens-cached` rather than inventing evidence.

The exact ratio reconstruction retains both published test counts and their shared source-fragment population. Source references pin declarations, not coherent multi-item snapshots or current truth. The first release does not average percentages or infer disjointness. When a complete explanation cannot fit, it returns a measured budget refusal with all denominator and dependency witnesses intact.

The complete public [receipt](real-data-receipt.json) includes every expected and actual rational, source pin and emitted-module digest. Its implementation digest identifies the tested JavaScript inventory independently of Git.

The NASA document and repository-owned policy examples are explicitly anchored in two native scratch-tracker source items before quantities reference them. Their genuine native item hashes and public item snapshots are in the receipt; document content digests remain separate. The runtime does not automatically fetch or copy these documents.

`test/corpus-privacy.test.ts` rejects non-public fleet names in the harvester, fixture and receipt; checks the policy digest against the committed document; and constrains the harvester's filesystem, Git and SDK read entry points. Negative controls cover an unapproved file read, a native read redirected from a copy to its source checkout, an unapproved archive root and new read capabilities. The release revert gate independently redirects the SDK root in a disposable copy and requires this guard to fail.
